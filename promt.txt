### БЛОК 1: ПОЛНЫЙ РЕДИЗАЙН ИНТЕРФЕЙСА (UI/UX)

1. **Полностью переработай дизайн всех страниц.**
   - Интерфейс должен ощущаться **лёгким и воздушным**.
   - Используй большие отступы (padding/margin), "дыхание" между элементами.
   - Размытые полупрозрачные фоны (glassmorphism), мягкие тени, плавные градиенты.
   - Анимации должны быть интуитивно понятными, плавными (плавность как у iOS), без рывков. Используй `transform` и `opacity` для анимаций, избегай `width/height` анимаций.
   - Все переходы (`transition`) должны быть с `cubic-bezier` для естественной плавности.
   - Исключи любые эмодзи в элементах UI (кроме клавиатуры для ввода смайлов в текст). Замени их на **векторные иконки** (SVG или иконочный шрифт, например, Lucide или Heroicons). Каждый элемент меню, кнопка, статус должны иметь свою уникальную векторную иконку.

2. **Адаптивная и responsive верстка для ВСЕХ устройств отдельно:**
   - Используй правильные breakpoints для телефонов, планшетов и десктопов.
   - При любом повороте экрана, уменьшении или увеличении окна интерфейс должен сохранять задуманный вид и функциональность.
   - Для телефонов: нижняя панель навигации, полноэкранные окна чатов и настроек.
   - Для планшетов: двухколоночный режим (список чатов слева, активный чат справа).
   - Для десктопов: трёхколоночный режим с возможностью менять размеры колонок.

### БЛОК 2: PWA ДЛЯ iPHONE И МОБИЛЬНАЯ ОПТИМИЗАЦИЯ

1. **Сделай из сайта полноценное веб-приложение (PWA), оптимизированное для iPhone:**
   - Добавь файл манифеста (`manifest.json`) с иконками всех размеров, названием приложения, стартовым URL и параметром `"display": "standalone"`.
   - Зарегистрируй Service Worker для кэширования и оффлайн-доступа.
   - Используй метатеги Apple для веб-приложений:
     - `<meta name="apple-mobile-web-app-capable" content="yes">`
     - `<meta name="apple-mobile-web-app-status-bar-style" content="black-translucent">`
     - `<meta name="viewport" content="width=device-width, initial-scale=1.0, viewport-fit=cover, user-scalable=no">`
   - Интерфейс должен учитывать зону Safe Area (для iPhone X и новее) — используй CSS `env(safe-area-inset-*)`.
   - Поддерживай жесты (например, свайп для возврата или вызова меню).

### БЛОК 3: СИСТЕМА ЗВОНКОВ (ВИДЕО И АУДИО)

1. **Почини полностью видео и голосовые звонки, чтобы работали идеально:**
   - Используй WebRTC с STUN/TURN серверами для стабильного соединения.
   - Обеспечь передачу аудио и видео между двумя и более участниками.

2. **Видео звонки:**
   - Собеседник должен видеть моё видео, а я — его (полноэкранное видео собеседника).
   - **Плавающая собственная камера:** моё видео отображается в маленьком окне, которое можно **перетаскивать (drag-and-drop)** в любой угол экрана во время звонка. Добавь кнопку для смены передней/задней камеры.
   - Элементы управления звонком (отключение микрофона, повесить трубку, переключение камеры) должны автоматически скрываться через 3 секунды бездействия и появляться при касании экрана.

3. **Голосовые вызовы:**
   - Корректная передача аудио (opus codec).
   - Визуальный экран звонка с аватаром собеседника, анимацией "волны" голоса и кнопками управления.

### БЛОК 4: МЕНЮ ДЕЙСТВИЙ НАД СООБЩЕНИЯМИ (КАК В TELEGRAM)

1. **Переработай меню редактирования, закрепления и удаления:**
   - Меню должно появляться **только при нажатии (тапе/клике) на сообщение**.
   - Оно должно возникать контекстно рядом с сообщением (попап или выпадающее меню).
   - В меню должны быть опции:
     - Редактировать (если моё сообщение)
     - Удалить
     - Закрепить/Открепить
     - Копировать текст
     - Переслать
   - Анимация появления — плавное масштабирование и изменение прозрачности.

2. **Система закреплённых сообщений:**
   - В верхней части чата отображается плашка с закреплённым сообщением (текст, имя автора).
   - При нажатии на плашку происходит скролл к закреплённому сообщению с подсветкой.
   - Возможность открепить сообщение через крестик на плашке.

### БЛОК 5: РЕГИСТРАЦИЯ И БАЗА ДАННЫХ

1. **Переработай систему регистрации и входа:**
   - При регистрации обязательные поля: email, пароль, имя пользователя (username).
   - **Проверка username в реальном времени:** как только пользователь вводит имя, отправляется запрос на сервер, и выводится статус "Занято" или "Свободно" с соответствующей иконкой.
   - Добавь поле email в базу данных (отдельная колонка в таблице users).
   - Пока подтверждение почты не активно, но структура для верификации должна быть готова (добавь колонку `email_verified_at` в базу данных).
   - Валидация email на фронтенде и бекенде.

2. **Подготовка базы данных для будущих приложений на Android/iOS:**
   - Бекенд должен быть построен как API-first (RESTful или GraphQL). Все запросы от будущих мобильных приложений будут идти через API на тот же сервер.
   - Структура базы данных должна поддерживать несколько платформ (единая таблица пользователей, устройств, токенов).
   - Добавь таблицу `sessions` или `refresh_tokens` для авторизации с разных устройств.

2. **Имя пользователя при регистрации:**
